# `results/` — comparison campaign output

One subdirectory per comparison task. Everything in here is generated by
`application/robotic_arm/comparison_driver.py` (the flights) and
`application/robotic_arm/comparison_plots.py` (the scoring and figures); see
`docs/docs_aerial_manipulator/Comparison Command.md` for how to reproduce it.

```
results/<task>/
  wb.npz             whole-body run: log, columns, the controller debug array,
                     the event list, and the whole reference table it flew
  l1.npz             geometric + L1 run, same format, same table
  metrics.json       every scored statistic, both controllers
  summary.md         the comparison table
  tracking_error.png base / EE / EE-heading / joint error against time
  error_ball.png     the error cloud + RMS sphere, both controllers together
  paths.png          commanded vs flown, base and end-effector
  logs/              driver, stack and Pegasus console logs for the two runs
```

| task | base does | arm does | end-effector | headline metric |
|---|---|---|---|---|
| `hover_arm_swing` | holds `(0, 0, 1)` | fold sweeps 80 -> 40 -> 80 deg, twice | follows the arm | **base** position error |
| `circle_ee_hold` | 25 mm circle + &plusmn;20 deg yaw | whatever pins the EE | **pinned** in the world | **EE** position error |
| `figure8_ee_updown` | 1.0 x 0.3 m figure-8 | fold sweeps 80 -> 50 deg, three times | bobs relative to the drone | base **and** EE tracking error |

Both runs of a task were commanded from the same trajectory table and flew the
same Isaac plant with the same allocator constants; only the control law and
its gains differ. The npz carries the table it flew (`tb_*` keys), so a run can
be re-scored without re-deriving anything.
