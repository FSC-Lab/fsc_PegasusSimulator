# T650 re-fit attempt, 2026-08-07 — two candidates tried, both rejected

Same discipline as 2026-08-06: **parameters only**, no modelling change, mass pinned at
3.033921 kg. Goal was one parameter set serving both the baseline flight (C) and the two
DIRECT-actuation flights (D1, D2).

**Outcome: the 2026-08-06 parameters were kept.** Neither candidate improved on them, and
the reason both failed is itself the most useful result here — the residual errors are
model-structure errors, not parameter errors, so no parameters-only fit can remove them.

Snapshot of the retained set and how to restore it: `backup_20260806/`.

## Candidate A — fit all three axes to the same-command plant test

The plant test (`plant_replay.py`, see `REPORT_direct.md` §3) drives the recorded motor
commands through the simulator's own model and compares the predicted rigid-body response
to the measured one. It is controller-independent, so in principle one fit serves both
modes. It gave:

| parameter | fitted | vs bench/CAD |
|---|---|---|
| `k` | 4.471957e-05 | 0.985× bench |
| `c` | 1.062613e-06 | 1.288× bench |
| Ixx / Iyy / Izz | 0.147742 / 0.146908 / 0.152928 | 2.56× / 2.29× / 2.35× CAD |

Plant-test gains duly moved from 0.16–0.50 to ~1.0. **Then the vehicle would not fly.**

| flight | z reached, candidate A | z reached, 2026-08-06 params |
|---|---|---|
| C (baseline) | **0.39 m** — never took off | 2.16 m |
| D1 (DIRECT) | **0.42 m** — never took off | 1.57 m |
| D2 (DIRECT) | 2.20 m | 2.20 m |

Two of three runs never left the ground; the drivers reported "takeoff did not settle in
90 s".

**Why this is evidence against the fit, not just an inconvenience.** The control gains are
shared verbatim with hardware and are not available to retune. The real vehicle flies well
on exactly those gains. If its roll/pitch inertia really were 2.4× the CAD value, the real
vehicle would be as unflyable as the simulation just became. It is not. So the plant test's
roll/pitch deficit is **not** inertia.

The likeliest explanation is unmodelled aerodynamic/rotor damping: it is stabilising, it is
present on the real aircraft, and it is entirely absent from `LaggedQuadraticThrustCurve`.
That is consistent with the regression diagnostic already noted in `REPORT_direct.md` §3b —
fitting `alpha = a·alpha_pred + b·omega` returns a non-physical **positive** `b`, meaning
inertia and damping are not separable from closed-loop data. Damping is a missing model
term, so it is out of scope for a parameters-only fit.

## Candidate B — move only the yaw axis

Since Ixx/Iyy could not move, the yaw correction was applied where it is still defensible:
yaw constrains only the ratio `c/Izz`, so Izz absorbed its share and `c` fell back to a
physical value.

- `Izz` = 0.152928 (2.35× CAD), `c` = 1.062613e-06 (1.288× bench)
- Net: yaw authority `c/Izz` × **0.183** — exactly the plant-test correction
- Roll, pitch, thrust and mass all left at the 2026-08-06 values, so takeoff was unaffected
- Plant-test yaw gain moved 0.20 / 0.16 → **1.11 / 0.89**

All three flights flew. The closed-loop result was still worse in **both** modes:

| yaw overshoot | real | 2026-08-06 | candidate B |
|---|---|---|---|
| flight C (baseline) | 9.16 % | **7.80 %** | 63.39 % |
| D1 (DIRECT) | 15.63 % | 0.33 % | 41.71 % |

| yaw shape RMSE | 2026-08-06 | candidate B |
|---|---|---|
| flight C | **1.27°** | 8.49° |
| D1 | **7.58°** | 20.25° |

Position was essentially unaffected (flight C shape RMSE 0.0559 → 0.0755 m).

**Why an open-loop-correct fit made the closed loop worse.** Reducing yaw authority to the
open-loop-correct value left the simulated yaw axis badly under-damped, because the
simulator has no yaw damping either. The inflated `c` was compensating for *two* missing
terms at once — the rotor-inertia reaction `I_rotor·ω̇` **and** aerodynamic damping — and
removing it exposes the second.

## The mode conflict, quantified

Interpolating overshoot against the yaw-authority ratio between the two measured points:

| flight | best `c/Izz` ratio |
|---|---|
| C (baseline) | ~0.96 |
| D1 (DIRECT) | ~0.53 |

The two modes want yaw authorities differing by ~1.8×, from the same physical vehicle. No
single value satisfies both. Two contributors, neither fixable by fitting the plant:

- **DIRECT's `ratectl_ki_z` is 2× its PX4-equivalent**, deliberately doubled on the X650 to
  speed up yaw-trim convergence — a reason that does not apply to a simulation whose
  `ratectl_trim_z` is 0. That makes simulated DIRECT yaw stiffer than baseline for reasons
  that have nothing to do with the plant.
- **The hardware PX4 gains are unverified.** Baseline yaw closes through `MC_*` gains inside
  the Pixhawk, and no committed parameter dump exists to confirm they match the simulation's
  (see `REPORT_direct.md`). If they differ, the flight C yaw comparison is not like-for-like.

Validated across all three flights, using the same step-selection rules everywhere (steps
with holds under 5 s, direction-ambiguous yaw steps, and the final landing descent are

| | flight C (baseline) | D1 (DIRECT) | D2 (DIRECT) |
|---|---|---|---|
| steps used | 16 of 18 | 12 of 13 | 16 of 20 |
| position shape RMSE | **0.056 m** | 0.240 m | 0.259 m |
| position overshoot bias | +2.7 pts | −3.5 pts | −6.6 pts |
| position rise bias | −0.24 s | −0.51 s | −0.73 s |
| yaw shape RMSE | **1.27°** | 7.58° | 7.31° |
| yaw overshoot, real → sim | 9.2 → 7.8 % | 15.6 → **0.3 %** | 22.7 → **0.1 %** |

Position agrees well everywhere and yaw agrees well in baseline. **DIRECT yaw does not** —
the simulation reaches the target fast with essentially no overshoot while the real vehicle
overshoots 16–23 %. Those yaw steps should be read as unmatched rather than as a validated
prediction.

## What would actually fix this

None of it is parameter tuning:

1. **Add `I_rotor·ω̇`** to `LaggedQuadraticThrustCurve` (~4 lines; ω̇ is already available
   from the lag update). Lets `c` return to bench.
2. **Add rotor/aerodynamic damping**, the term candidate A's failure points at. Until it
   exists, roll/pitch/yaw authority and damping cannot be separated from flight data.
3. **Measure roll/pitch inertia** independently (bifilar pendulum or T650 CAD) so the
   damping-vs-inertia ambiguity is closed by measurement rather than by fitting.
4. **Dump the hardware PX4 gains** and commit them, so the baseline comparison is verifiably
   like-for-like.
