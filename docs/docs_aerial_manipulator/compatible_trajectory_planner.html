Compatible Trajectory Planner

What the planner takes in, what it streams out, and the problem it actually solves — written in the form of an optimization problem so that what is solved, what is frozen by fiat, and what is free but unused can be told apart.

Part A

Compatible trajectory generation

Given two complete rest configurations, solve for the reference between them. This is where the underactuation enters, and where almost every choice is made by fiat rather than by search. Where the goal configuration comes from is Part B.

§1 The problem

Everything on this page unpacks one statement. Read it first; the rest is what each of its parts turns out to be.

minimize   J [ re(·), b1e(·), b1(·), σ(·), T ]
over       the EE path, the two heading paths, the null-space schedule, and the duration
subject to   (A3)–(A6) at every t, giving xc(t)   compatibility
            Qmin ≤ q(t) ≤ Qmax,   σnd(q) ≥ 0.10,   β ≥ 5°   path
            rest conditions at t = 0 and t = T
            ‖u1‖ ≤ umax,   ‖τj‖ ≤ τmax — not present today
(P)

every symbol is a link — click through to where it is defined, decided, or discarded

Interface

A rest-to-rest transition between two static holds. Both endpoints are full configurations, not just goals — the planner needs the start as much as the finish. Part B is how the goal configuration is obtained from operator setpoints; Part A — this part — is how the trajectory between two configurations is solved.

The coupled model: 5 link masses, joint axes hi, link offsets li, link CoM offsets ci, and the bare-airframe CoM.

Kinematic bounds and numerics: v_max 0.30 m/s, a_max 0.15 m/s², w_max 0.30 rad/s, T_min 3 s, polynomial degree 16, 201-point solve grid, 801-point check grid.

{ T, ref(t), q1, diag }  or  ValueError

Degree 16 is not arbitrary: the message carries the CoM through its fourth derivative, so the polynomial must survive four exact differentiations. q̇d is the one numerically-differentiated field in the message — a central difference with h = 1 ms, because the joint-recovery map is not differentiated in closed form.

§2 The relations that make a trajectory “compatible”

Compatible means the CoM path is consistent with the attitude that its own acceleration demands. That is a loop, and the loop is the whole problem.

Model

Four joints, axes h = (z, x, x, z). Forward kinematics on the chain gives the end-effector and the system centre of mass, both in the base frame:

Ri = Ri−1 Rot(hi, qi),    Oi = Oi−1 + Ri li r_0e = O_n  ·  r_0c = (1/m)[ m₀c₀ + Σᵢ mᵢ(O_{i−1} + Rᵢcᵢ) ]
(A1)

Joints 2 and 3 share the x axis. That single fact governs everything below: the arm's orientation depends on q2 and q3 only through their sum.

Rest points are exact

At rest the thrust is vertical, so R0 = Rz(φ) and the whole reference closes in algebra, with every derivative zero:

xc = xb + Rz(φ) r0c(q),    re = xb + Rz(φ) r0e(q) both endpoints hit their holds algebraically — no fitting error to absorb
(A2)

The compatibility loop

Away from rest, four relations close on themselves. Read them as a cycle:

ac = ẍc + g e3,    b3 = ac / ‖ac‖ thrust must point along the CoM acceleration — the underactuation constraint
(A3)
R0 = build(b3, b1),    (α, β, γ) = zxz(R0T Re) attitude from thrust direction + heading; arm angles from the residual rotation
(A4)
q = [ α,   σβ,   (1−σ)β,   γ ] three angles, four joints — σ is not determined by the task
(A5)
xc = re + R0 ( r0c(q) − r0e(q) ) closes the loop: x_c depends on ẍ_c through (A3)–(A5)
(A6)

Where (A6) comes from

  1. Definitions from (A1), both referenced to the body origin O0 = 0: r0e = On       r0c = (1/m) [ m0c0 + Σi mi( Oi−1 + Rici ) ],   m = Σi mi
  2. A point at body-frame offset v, in the world: p = xb + R0 v
  3. Applied to each: re = xb + R0 r0e(q)       xc = xb + R0 r0c(q)
  4. Subtract; xb cancels: xc − re = R0 ( r0c − r0e )   ⟹   xc = re + R0 ( r0c − r0e )   = (A6)

Exact for arbitrary R0 — no small angle, no rest condition, no dynamics. Verified to 8.9e−16 m over 500 random (q, xb, R0).

Substituting (A3)–(A5) into (A6) eliminates R0 and q, leaving xc alone on both sides:

Substitution

  1. (A3) — thrust direction, as a functional of the unknown: b3[xc] = ( ẍc + g e3 ) / ‖ ẍc + g e3 ‖
  2. (A4) — attitude, with Π = I − b3b3T: b1c = Π b1 / ‖Π b1‖,    b2c = b3 × b1c   ⟹   B[xc] = [ b1c   b2c   b3 ]
  3. (A4) + (A5) — joints, with Λ(M, σ) = [ a, σb, (1−σ)b, c ] and (a, b, c) = zxz(M): q[xc] = Λ( B[xc]T Re, σ )
  4. into (A6), with Δ(q) = r0c(q) − r0e(q)  ⟹  (A7)
xc = re + B[xc]  Δ( Λ( B[xc]T Re, σ ) )  ≡  F[xc] r_e, R_e, b1, sigma are prescribed data — x_c is the only unknown
(A7)

F depends on xc only through ẍc, and pointwise in t: at each instant (A7) is algebraic in (xc, ẍc). Coupling across time enters solely through the polynomial, so on its coefficients C (3 × 17) the fixed point is

C ← Fit { F[ pc(· ; C) ](tk) },    k = 1 … 201 fit -> differentiate -> evaluate -> refit: the Picard scheme of §4
(A8)

Differential flatness with a loop in it: the flat outputs would determine everything, except that one of them is defined through its own second derivative. An independent implementation of (A7) reproduces the planner's defect exactly — 5.48e−08 m.

Equation (A5) hides a degree of freedom

The z-x-z decomposition returns three angles for four joints. The split σ — how β divides between q2 and q3 — is unconstrained by the task. Measured, holding (α, β, γ) fixed and varying only σ:

The EE heading is invariant; the EE position sweeps 10.6 cm, and the CoM offset moves with it. So σ is a real, consequential null space — one scalar function of time, free at every instant.

§3 What the implementation does with (P)

The general problem stated at the top is an infinite-dimensional trajectory optimization. What the implementation solves is that problem with almost every decision variable pinned and the cost function removed — variable by variable:

What the implementation does with each variable

Decision variableStatusValue imposed
re(t) — EE path prescribed p_e0 + Δp · s(t)  — a straight line
α, β, γ, ψ — the four angle channels prescribed linear in s(t), endpoint to endpoint
s(t) — the timing profile prescribed one shared septic min-snap, all channels
σ(t) — the null space free, unused σ₀ + (σ₁ − σ₀) · s(t)  — linear, arbitrary
T — duration prescribed closed form from peak-factor bounds
xc(t) — the CoM solved the only remaining unknown
J — the cost absent J ≡ 0. Nothing is minimized.

With every path variable pinned, (P) collapses to a feasibility problem with a unique solution: find the xc consistent with its own thrust direction. No search, no trade-off, no objective — which is why calling it an optimization would be generous.

Why min-snap is structural, not stylistic

The solved CoM's velocity depends on the prescribed jerk, because R0 rotates with ẍc′ through the thrust-direction map (A3). A min-jerk profile has jerk discontinuities at segment joins, which would step the solved CoM velocity there. The septic s = 35u4 − 84u5 + 70u6 − 20u7 zeroes velocity, acceleration and jerk at both ends.

solved

Genuinely determined and computed — the fixed point.

prescribed

Pinned to one shape by the implementation. Could be a decision variable.

free, unused

Mathematically unconstrained, and resolved arbitrarily.

verified

Tested after the fact. Violations cause refusal, never a re-solve.

§4 How the fixed point is solved

Picard iteration on a degree-16 polynomial. Assume a CoM, compute the arm pose its thrust direction implies, recompute the CoM that pose gives, refit, repeat.

// grid t_k, k = 1…201 over [0, T]; p_e, R_e, b1, b1e, σ from the prescribed task p_c(0) ← fitdeg 16( p_e ) seed: the EE path itself repeat for m = 0, 1, 2, … for each k: ac ← p̈_c(m)(tk) + g e₃ (A3) R₀ ← build( ac/‖ac‖, b₁(tk) ) (A4) q ← [α, σβ, (1−σ)β, γ] from zxz(R₀ᵀRe) (A4)(A5) yk ← pe(tk) + R₀ ( r0c(q) − r0e(q) ) (A6) p_c(m+1) ← fitdeg 16( y ) unconstrained least squares until maxk ‖ p_c(m+1) − p_c(m) ‖ < 10⁻¹⁰ m

The iteration is a contraction because the arm's CoM-to-EE offset is small (≈0.2 m) compared with the lever the thrust direction exerts on it — each pass changes R0 only slightly. Measured on a combined base + arm transition:

The defect is the residual of (A6) on the 801-point check grid — 55 nanometres, so the returned trajectory is compatible to well below anything the plant could express. The 1.1 ms evaluation sits inside the governor's 10 ms budget at 100 Hz, but it runs in Python under the GIL, which is why the solve carries a yield hook: one uninterrupted Picard pass is ~26 ms and would otherwise stall the stream past its 250 ms staleness window.

Nothing below enters the solve. Every one is a test applied to the finished trajectory, and failing one raises rather than triggers a search.

§6 The cost of prescribing instead of searching

Because the path is fixed before feasibility is tested, a task that is perfectly achievable can be refused — on the strength of a choice the planner made, not the task's own geometry.

Sixty random goals from the folded home pose produced 19 refusals. Three of those had both endpoints legal and failed only because the prescribed path left the joint box. One of them, goal q = [−10.1, −12.5, 28.9, 98.2]°, refused because q3 reaches 55.0° against its +50° limit:

0.0080.040.0, 40.0 [+0.375, +0.625]
0.4555.10.3, 54.8 [+0.092, +0.908] violates
0.5048.2−6.3, 54.5 [−0.037, +1.037] violates
1.0016.4−12.5, 28.9 [−2.049, +3.049]

A legal schedule exists at every sample

5 of 21 samples violate a joint limit under the planner's linear σ. 21 of 21 admit some legal σ, and both endpoints sit inside their own ranges by construction. The plan is refused because of the interpolation, not because the task is infeasible.

One caveat, stated plainly: re-scheduling σ changes r0e and r0c, hence the CoM, hence the fixed point — so this is a necessary condition, not proof that a re-solve converges. It does rule out “the task is impossible”.

That makes σ(t) the cheapest place to start: it is already a free function, it is already computed every iteration, and constraining it against the joint box and the singularity margin needs no change to the compatibility machinery. The prescribed EE path, the shared timing profile and the duration are the larger prizes, and the ones that would require a real solver.

Part B

Inverse kinematics — setpoints to a goal configuration

Part A assumed both endpoints were complete configurations. Only the start one is measured; the goal has to be built from what the two ground stations actually send — a base pose and, optionally, an end-effector pose. The order in which that is done constrains everything Part A then sees.

§7 What the goal configuration is made of

The base is settled first, from the drone ground station. Only then is the arm asked anything — and in two of the three cases it is not asked at all.

(xb1, φ1) ← pending base target, else the current hold's base the base pose is FIXED before the arm problem is posed
(B1)
Caseq₁ comes fromIK?
go_home Trigger the folded home pose [0, 40°, 40°, 0] no
base target only — “ride-along” the current hold's q, unchanged: the arm keeps its pose while the base flies no
EE target present ik_world(params, x_b1, φ1, p_e, az, q_seed = hold q) yes

This is not a whole-body IK

Because (B1) pins the base before the arm is solved, an end-effector target that is perfectly reachable with a slightly different base pose is refused — the base is not a decision variable at this stage. Structurally the same failure as the prescribed path in Part A: something is fixed first, the remainder is then found infeasible, and there is no way back.

§8 The 4-DOF task and its residual

Four scalar constraints against four joints — square by design, matching the law's own task variable y = [re; b1e].

World to base frame

The goal is a rest point, so the thrust is vertical and R0 = Rz(φ) exactly — there is no roll or pitch to account for, and the whole task reduces to the base frame:

rerel = Rz(φ)T ( peworld − xb ),     azrel = azworld − φ exact only because the endpoint is a REST point
(B2)

The residual

f(q) = [  r0e(q) − rerel  ∈ ℝ³  ;  wrap( azrel − az(q) )  ∈ ℝ¹ ] 3 position + 1 heading = 4 equations, 4 unknowns
(B3)
az(q) = atan2( b1e[1], b1e[0] ),    wrap(d) = atan2( sin d, cos d ) horizontal projection of the EE's first axis; wrapping removes the branch cut
(B4)

Both r0e and Re come from the same exact chain the controller uses (A1), not a simplified model — so a converged IK solution is consistent with the law's own kinematics by construction.

Only the azimuth is constrained, not the full orientation. The remaining two end-effector orientation degrees of freedom are whatever the position solution happens to produce. That matches the task variable the law tracks, but it does mean an operator cannot command a full EE pose. If b1e comes out near-vertical the azimuth is undefined and the solve raises rather than returning nonsense.

§9 Gauss–Newton with a finite-difference Jacobian

No analytic Jacobian, no damping factor, no joint limits in the loop.

seeds = [ q_seed (current hold), folded home [0,40°,40°,0], zeros ] for each seed: q ← seed for 80 iterations: f ← f(q) (B3) if ‖f‖ < 1e-10: break for j = 1…4: J[:,j] ← ( f(q + ε ej) − f ) / ε ε = 1e-6, forward difference dq ← lstsq( J, −f ) SVD pseudo-inverse, rcond=None if ‖dq‖ > 0.5: dq ← dq · 0.5/‖dq‖ step cap, radians q ← q + dq keep the lowest residual; stop early if ‖f‖ < 1e-8

Two things stand in for damping, and neither is Levenberg–Marquardt: there is no λ and no (JTJ + λI)−1. Instead, lstsq pseudo-inverts through an SVD, so ill-conditioned directions near a singularity are truncated rather than amplified; and a 0.5 rad step cap bounds the Newton step without changing its direction.

The Jacobian is numerical — four extra forward-kinematics evaluations per iteration. For a 4-DOF arm that is cheap enough that nobody derived the analytic form. The three seeds are the only defence against multiple IK branches: there is no global search and no branch enumeration, so a solution reachable only from a fourth basin is simply missed. Seeding from the current hold biases the answer toward the pose nearest where the arm already is.

Limits are not in the loop — and the failure is returned, not discarded

There is no clamping, no projection, no barrier. The iterate is free to wander outside the joint box and come back, and a converged solution outside the box is reported, never corrected. Same verify-don't-enforce pattern as Part A, with the same consequence: an out-of-range solution is a refusal even where a legal alternative branch may exist.

q1 comes back even when the solve fails, on purpose — that is what feeds whole_body_governor/target_joints, published on every plan attempt including infeasible ones, so the arm ground station's joint row can show which joint went out and by how much rather than just “infeasible”.
